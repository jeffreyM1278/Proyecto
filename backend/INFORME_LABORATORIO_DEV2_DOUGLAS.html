3. Criterio 2: Avance de Backend, API y Base de Datos (25%)

3.1. Script de Conexión a Base de Datos (SQL Server / MySQL)

El archivo src/config/database.js implementa Sequelize con *Connection Pooling* (máximo 10 conexiones simultáneas), soporte para zona horaria de El Salvador (CST -06:00) y dialecto dinámico configurable por variable de entorno para adaptarse al motor seleccionado por el equipo: 

import { Sequelize } from 'sequelize';
import config from './index.js';

const dialect = config.db.dialect || 'mssql'; // Soporta SQL Server (diseño de Miguel) o MySQL

const sequelize = new Sequelize(
  config.db.name,
  config.db.user,
  config.db.password,
  {
    host: config.db.host,
    port: config.db.port,
    dialect,
    pool: { max: 10, min: 0, acquire: 30000, idle: 10000 },
    logging: config.app.env === 'development' ? console.log : false,
    dialectOptions: dialect === 'mssql' ? {
      options: { encrypt: false, trustServerCertificate: true, enableArithAbort: true }
    } : {}
  }
);

export default sequelize;

4. Lógica Core de Negocio (Valor Agregado del Desarrollador 2)

El aporte diferencial del rol de Douglas Moran consiste en la automatización del mantenimiento preventivo mediante dos algoritmos implementados en src/services/maintenanceService.js:

4.1. Algoritmo de Cálculo de Fechas Preventivas

Procesa la última fecha de mantenimiento y la frecuencia establecida en el plan del equipo:

Fórmula:
FechaPróxima = FechaÚltimoMantenimiento + (FrecuenciaValor × FrecuenciaUnidad)
DíasRestantes = FechaPróxima - FechaActual
  • VENCIDO (< 0 días): Genera alerta crítica roja. Requiere intervención inmediata.
  • PRÓXIMO (0 a 7 días): Genera alerta preventiva ámbar. Candidato para orden de trabajo.
  • AL DÍA (> 7 días): Equipo en estado conforme verde.

4.2. Generador Automático de Órdenes sin Duplicados

Invocado mediante POST /api/v1/maintenance/generate-orders:

  1. Identifica todos los equipos activos con estado VENCIDO o PRÓXIMO (≤ 7 días).
  2. Verifica en OrdenesMantenimiento que NO exista ya una orden preventiva abierta (en estado PENDIENTE o EN_PROGRESO) para dicho equipo.
  3. Si no existe orden previa, crea la orden preventiva con prioridad calculada (ALTA si está vencida, MEDIA si es próxima) y fecha programada.
  4. Retorna un reporte detallando cuántas órdenes se crearon y cuántas se omitieron por ya estar en trámite.

5. Criterio 3: Infraestructura AWS Cloud y Seguridad Inicial (25%)

5.1. Almacenamiento en Amazon S3 con URLs Prefirmadas

Los manuales técnicos y fichas en PDF no se almacenan como binarios en la base de datos para no degradar el rendimiento relacional. Se utiliza el bucket de Amazon S3:

  • Carga: Se sube mediante PutObjectCommand del SDK oficial @aws-sdk/client-s3.
  • Descarga Segura: El bucket se mantiene totalmente privado. Para visualizar o descargar un documento, el endpoint GET /api/v1/documents/:id/download genera una URL prefirmada temporal (con expiración de 15 minutos) usando @aws-sdk/s3-request-presigner.

5.2. Control de Acceso Basado en Roles (AWS IAM / RBAC)

Se configuró un middleware de autorización que restringe las acciones según el rol del usuario:

  • ADMIN: Acceso total. Único perfil autorizado para operaciones DELETE.
  • SUPERVISOR: Lectura total, creación y actualización de órdenes y programación.
  • TECNICO: Visualización de órdenes asignadas, actualización de diagnósticos y bitácora técnica.
